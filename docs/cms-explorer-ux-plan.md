# CMS Explorer UX implementation plan

## Inspection / baseline
Read AGENTS, current product/architecture/URL guides, scans and CMS changes, and archived Phase C provider plan (the original file now lives under docs/archive/2026-09).
Route: `src/app/dashboard/sites/[id]/cms/page.tsx`; UI: `metadata-refresh.tsx`, `live-cms-items.tsx`; server action: `explorer-actions.ts`; authoritative reader: `sites/service.ts::loadSiteContent`.
Current path: open Explorer, choose collection, optionally refresh schema, expand fields, click Load items (4–5 actions). GET uses `readMetadata` for collections and selected schema: W/I 0/0, including expired structure. Two prominent refresh controls and an expired banner obscure that structure remains usable. Live load/pagination uses 4 W / 1 I: authorized sites, collection membership, schema and 25 items. Every page repeats this work. Mounted UI retains one page only; changing collection discards it. No meaningful session reuse or retry lockout exists.

## Proposed slices, in order
1. Compact saved-structure freshness and one secondary refresh icon. Remove blocking expiry messaging. Keep stale fields browsable. No request changes.
2. Client collection selection is the live-read intent; GET/direct URLs never initiate reads. Keep layout stable with row skeletons. Use existing safe live loader, no new write/scan contract.
3. Bounded in-memory cache owned by the mounted Explorer, no storage persistence or distributed cache. Keys: actor/workspace/site/connection/generation/collection/offset/locale. Two-minute initial freshness ceiling (lowest requested range, limits stale item exposure; not a measured optimum), at most 12 pages. No timer fetches. Coalesce same-page requests. Current DB scope check before cache reuse; never use a cached response as authorization. Unmount/logout discards state; route scope/generation changes remount it. Explicit refresh clears all pages; locale is part of key. No locale selector is currently implemented; existing default locale remains unchanged.
4. Reuse requested pages and display content load time; search filters only the loaded page. No prefetch/hover fetch. Item count comes only from actual response. Preserve readable field inspection.
5. Catch failures without hiding structure, retry explicitly, enforce connection-scoped Retry-After locally across collections. Server still validates every uncached read. No automatic retries; missing retry timing for 429 defaults conservatively to 60 seconds. Drop late results after scope/generation changes.

## Budgets and invalidation
Open/GET/cached structure: 0W/0I before and after. Explicit uncached selection: existing4W/1I, now without extra load click. Valid cached selection/page:4W/1I →0W/0I, with DB scope validation. Expired item cache: only a new explicit selection/page/retry triggers4W/1I. Manual metadata refresh retains collections2W/1I or selected schema3W/1I. E/G +0 throughout; no scan/quota/AI/worker changes. Cache rows never enter persisted structure. Explicit refresh invalidates content before request; known connection generation and structure timestamp changes invalidate it. Independent writes remain fresh and authoritative.
